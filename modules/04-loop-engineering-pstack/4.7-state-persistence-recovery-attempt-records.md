# 4.7 State Persistence, Recovery & Attempt Records

- A loop that lives only in a conversation dies with it. Persisting state makes the workflow survive interruption, compaction, crashes, and handover.
- Minimum state for a loop: the goal and criteria, the current stage, completed steps with their evidence, the attempt count, and the next action.
- An attempt record logs each try: what was changed, what was observed, and the conclusion. It prevents the most wasteful failure — repeating an approach that already failed.
- Recovery means a fresh session can read the state and continue from the last verified point. Design for it by making steps safe to re-run and by recording what was verified, not just what was done.
- Write state at stage boundaries and after each verified step. State written only at the end is not state; it is a report.
- Version control is part of the state: small commits at verified points give exact recovery positions, and the diff since the last one shows what the current attempt has changed.
- Re-verify on resume. Recorded state describes the past; a quick check that the tests still pass protects against changes that happened in between.
- Keep it proportionate: a short structured file is enough. A state system more complicated than the task it tracks is a new source of failure.
