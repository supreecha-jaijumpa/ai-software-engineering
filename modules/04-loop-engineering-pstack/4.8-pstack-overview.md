# 4.8 Pstack Overview — Control App, Feature Map, /verify-feature

- Pstack (Poteto Stack) is a project-specific workflow concept — one concrete packaging of loop engineering — not an industry standard. Judge it by whether it helps your project, and change it freely.
- It has three components. The Control App controls tasks, workflow stages, and task status. The Feature Map represents feature scope, dependencies, and impact. `/verify-feature` verifies requirements, implementation, and evidence.
- The suggested flow: requirement → Control App creates the task and defines scope → Feature Map maps modules, dependencies, and impact → technical plan and human approval → implementation loop → tests and deterministic quality checks → `/verify-feature`.
- Verification has three outcomes: fail → diagnose, fix, verify again (bounded); blocked → report and request a human decision; pass → human review → complete.
- Each component answers one question: where are we (Control App), what does this touch (Feature Map), and is it really done (`/verify-feature`).
- The components communicate through artifacts — a task record, a map file, a verification report — which keeps every stage inspectable and resumable.
- Possible extensions: task state management, a feature dependency graph, persistent state and recovery, execution logs, human approval gates, automated verification, retry limits and failure classification, workflow observability. Add them when a real problem asks for them.
- "Control App" names a responsibility, not necessarily an application. A Markdown task file with clear states is a valid first implementation.
