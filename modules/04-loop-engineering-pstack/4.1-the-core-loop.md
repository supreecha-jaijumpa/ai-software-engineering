# 4.1 The Core Loop — Goal, Action, Observation, Evaluation, Adjustment

- Loop engineering treats AI work as a control loop rather than a single instruction: set a goal, act, observe the real result, evaluate it against criteria, adjust, and repeat until done or stopped.
- Goal: what must be true at the end, stated so that it can be checked. "Make the checkout better" cannot drive a loop; "the three acceptance criteria in the task file pass" can.
- Action: a bounded change — an edit, a command — small enough that its effect can be attributed. Observation: what actually happened, taken from the system (test output, exit codes, the diff), not from the agent's description of it.
- Evaluation: comparing the observation with the criteria. This is the step most often skipped or faked; without it, the loop is just repeated guessing.
- Adjustment: choosing the next action from the evidence — fix, try a different approach, or stop and escalate.
- A one-shot prompt is a loop with one iteration and no evaluation. It works for easy tasks and fails silently on hard ones.
- A complete loop also has a retry bound, a stop condition, an escalation path, and a record of attempts — the remaining topics of this module.
- The engineering mindset: you are not writing the instruction that produces correct code; you are designing the system that notices incorrect code and responds to it.
