# 6.7 Evaluation Engineering — Workflow Metrics

- Evaluation engineering means measuring the quality of an AI workflow instead of relying on impressions. "It feels better since I added the reviewer agent" is a hypothesis; a measured difference is a result.
- Outcome metrics: Task Success Rate (tasks meeting acceptance criteria), First-pass Success (passing verification without rework), Regression Rate (regressions introduced), Test Pass Rate (relevant tests passing).
- Effort metrics: Rework Rate (how much correction was required), Human Intervention (corrections or decisions a human had to make), Cycle Time (task start to verified completion), Token per Successful Task (consumption for verified outcomes).
- Read metrics together. Fewer tokens with more rework is not an improvement; faster cycle time with more regressions is a loss.
- Define each metric precisely before measuring — what counts as success, what counts as an intervention — or the numbers will drift with your mood.
- A metric needs a reliable source: verification reports, task state history, the execution log, usage reports. If it has to be reconstructed from memory, it is not being measured.
- Beware optimizing the number. A success rate can be raised by picking easy tasks or loosening criteria; keep the tasks and the criteria fixed when comparing.
- Start with two or three metrics you will actually record for every task. A complete dashboard that nobody maintains measures nothing.
