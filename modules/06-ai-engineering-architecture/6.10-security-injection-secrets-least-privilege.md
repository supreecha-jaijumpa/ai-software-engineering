# 6.10 Security — Prompt Injection, Secrets & Least Privilege

- An AI coding agent reads untrusted text and can execute actions. Security work is keeping the first from controlling the second.
- Untrusted repository content includes more than strangers' code: dependencies, issue and PR text, fetched web pages, logs, generated files, and MCP tool results can all carry instructions aimed at the agent.
- Assume injection cannot be fully prevented by wording. Design so that a successful injection finds little to do: limited tools, limited files, limited network, limited credentials.
- Secret and credential protection: keep secrets out of the repository and out of the context, deny the agent read access to credential files, give it scoped and short-lived tokens, and never paste production credentials into a session.
- Least-privilege tool access: each agent and each task gets only the tools and permissions it needs — read-only for research and review, write access limited to the task's scope.
- Command and file permissions plus sandboxing bound the damage of a wrong or manipulated action. Exfiltration needs an outbound channel, so restricting network access removes a whole class of attack.
- External MCP servers add data-exposure and supply-chain risk: they see what you send them, they return content the agent will read, and they can change after you approved them.
- Test your defenses safely: in a throwaway repository with no real secrets, plant a misleading instruction in a file or fetched document and observe whether the workflow follows it, asks, or blocks. Record the result as evidence.
