# 8.3 From Implementation to QA Handoff

- Stage 6, implementation: make small, scoped changes, follow existing conventions, keep changes traceable to requirements. Small steps keep each verification meaningful and each failure attributable.
- Stage 7, verification: run the relevant tests; run type check, lint, and build as appropriate; verify the acceptance criteria; inspect the diff. This is `/verify-feature` territory — evidence per criterion.
- Stage 8, review: correctness and edge cases, security and performance where relevant, maintainability and regressions — by a reviewer independent of the implementation.
- Stage 9, correction loop: diagnose failures using evidence, make bounded corrections, re-run the relevant verification, and escalate if blocked or unsafe. The loop has a retry limit and a record of attempts.
- Stage 10, human final review: confirm behavior and scope, approve the final changes. The human reads the diff and the evidence — not just the summary.
- Stage 11, QA handoff: summarize the changes, provide test evidence, list limitations and known issues, update relevant documentation.
- A good handoff lets QA start without asking questions: what changed, how to exercise it, what was tested and how, what was not tested, and where the risks are.
- The common failure in this half is the unverified claim — "implemented and tested" with no output behind it. The workflow must be built so that it cannot report success without evidence.
