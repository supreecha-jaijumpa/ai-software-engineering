# 8.2 From Requirement Intake to Human Plan Approval

- Stage 1, requirement intake: understand the business goal, clarify ambiguity, define scope and acceptance criteria. The output is a requirement you could hand to someone else without further explanation.
- The agent's most valuable contribution at intake is questions — gaps, contradictions, unstated edge cases — not solutions. Unanswered questions are recorded as open, not silently resolved.
- Stage 2, codebase exploration: inspect architecture and conventions, find related features and tests, identify dependencies and risks. It is read-only, and a good candidate for a subagent that returns findings with file references.
- Stage 3, feature mapping: identify affected modules, map dependencies and data flow, record impact and unknowns. The map becomes the shared context for everything that follows.
- Stage 4, technical specification: define the design and the contracts, identify schema and API changes, define the test strategy. Each requirement should be traceable to a part of the plan and to a planned test.
- Stage 5, human plan approval: review scope, risks, and trade-offs; approve or revise. Nothing is implemented before this gate for high-impact changes.
- A reviewable plan is short and specific: what changes where, in what order, how it will be verified, what is explicitly out of scope, and which risks were accepted.
- The common failure in this half is rushing: an agent that starts coding during intake has replaced four stages with a guess. Keep the early stages read-only by permission, not only by instruction.
