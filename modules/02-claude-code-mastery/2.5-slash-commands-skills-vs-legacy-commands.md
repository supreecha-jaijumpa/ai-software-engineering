# 2.5 Slash Commands — Skills vs Legacy Custom Commands

- Typing `/` invokes a command. Some are built into Claude Code (`/clear`, `/compact`, `/context`, `/memory`, `/permissions`, `/resume` and others); others are defined by you, your project, or a plugin.
- Historically, custom commands were single Markdown files in `.claude/commands/` — a saved prompt you trigger by name, optionally with arguments.
- Skills have absorbed that role: a skill also creates a `/name` invocation, and adds a folder for supporting files, frontmatter options, and the ability for Claude to load it automatically.
- Existing `.claude/commands/` files keep working, so both forms exist in real repositories — including this classroom. For new work the skill format is the current convention; verify the exact relationship in the current docs.
- The useful distinction is not the file location but **who triggers it**: you explicitly (a command-like workflow such as `/commit` or `/verify-feature`), or the model when it judges the content relevant (knowledge-like skills).
- Workflows with side effects — deploying, committing, sending messages — should be user-triggered only, so the model cannot decide to run them by itself.
- Arguments (`/fix-issue 123`) make one command reusable, but a command that needs a paragraph of arguments is really a conversation.
- Keep the command list short and well named: each one is something people must remember exists, and something that must be kept working.
