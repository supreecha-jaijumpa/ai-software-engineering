# 2.12 Session Continuity, Compaction & Resuming Work

- A session's context fills up as work proceeds. When it approaches the limit, Claude Code compacts it — the older conversation is replaced by a summary so that work can continue.
- Compaction is lossy: exact file contents, earlier error messages, and nuances of a decision can disappear. Instruction files are reloaded, but what you said only in chat is at the mercy of the summary.
- `/compact` triggers it deliberately and can be given a focus (what to preserve); `/clear` starts over with an empty context. Clearing between unrelated tasks is usually better than letting one session accumulate everything.
- Sessions are stored locally and can be continued (`claude --continue` for the most recent one) or picked from a list (`claude --resume`). Resuming restores the conversation, not the state of the world — files may have changed meanwhile.
- Checkpoints record file edits so that you can rewind the code, the conversation, or both when a direction turns out wrong.
- For work that spans sessions, do not rely on the transcript. Write the state down: the goal, decisions made, what is done, what is next, and how to verify — in a short handoff file.
- A fresh session reading a good handoff note is often more reliable than a long, compacted one: it starts with a clean context and only the relevant facts.
- Warning signs that it is time to compact or restart: instructions being forgotten, a mistake being repeated after correction, or unrelated earlier work bleeding into the current task.
