# 2.6 Agents & Subagents

- A subagent is a separate agent instance that the main session delegates a task to. It works in its own context window with its own instructions and tools, and returns only a final result.
- Definitions live in `.claude/agents/` (project) or `~/.claude/agents/` (user) as Markdown files: frontmatter with a name, a description of when to use it, optionally the allowed tools and model, and a body that serves as its system prompt.
- The main benefit is context isolation: a research task that reads fifty files costs the main conversation only the summary that comes back.
- The second benefit is specialization and restriction — a reviewer or researcher that has read-only tools cannot modify code, whatever it decides.
- The price: a subagent starts with none of your conversation. It knows only its definition and the task message it receives, so the delegation brief must contain the goal, the scope, and the expected output format.
- Information is lost at both handoffs — what you did not put in the brief, and what the subagent did not put in its summary. Mistakes come back in the same confident tone as findings.
- Subagents cost extra tokens and time, and they cannot hold a conversation with you while working. Do not delegate what a couple of direct tool calls would answer.
- "Agent" here means a definition (role, tools, prompt); "subagent" means that definition running on a delegated task. Coordinating several of them is the subject of Level 5.
