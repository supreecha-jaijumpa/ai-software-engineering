# 2.11 Built-in Tools, Terminal Workflows & Git Integration

- Claude Code ships with tools for reading files, searching by file name and by content, editing and writing files, running shell commands, fetching and searching the web, tracking tasks, and delegating to subagents.
- Search before read: a targeted name or content search costs a fraction of the tokens of opening whole files, and it is how good exploration of an unfamiliar codebase starts.
- The shell tool makes everything in your terminal available — test runners, linters, build tools, `git`, `gh`, project scripts. Any CLI you already trust is an integration that needs no extra setup.
- Command output goes into the context. Prefer quiet flags, filters, and "failures only" output over full verbose logs.
- Git is the safety net of agentic work: start from a clean tree, work on a branch, commit small steps, and read the diff before accepting a change.
- Claude can write commit messages, create branches, and open pull requests through `git` and `gh` — treat pushing and PR creation as outward-facing actions that deserve an approval step.
- Long-running commands (dev servers, watchers) can run in the background while work continues; know how to see and stop them.
- A productive pattern for larger changes: explore (read-only) → plan → implement in small steps → verify with real commands → review the diff → commit.
