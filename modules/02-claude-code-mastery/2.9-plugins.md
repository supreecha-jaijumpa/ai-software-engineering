# 2.9 Plugins & Capability Packaging

- A plugin is a package that bundles Claude Code extensions — skills and commands, agents, hooks, and MCP server configuration — so they can be installed, versioned, and shared as one unit.
- Plugins are distributed through marketplaces (a catalog, typically a Git repository) and managed with the `/plugin` command; a team can also host its own marketplace.
- The problem they solve is distribution: without a plugin, sharing a workflow across repositories means copying folders and hoping they stay in sync.
- Use project files (`.claude/` in the repository) for things specific to one codebase; use a plugin for capabilities that several repositories or teams should share.
- A plugin is not a new kind of capability — everything inside it is one of the mechanisms from the earlier topics, with the same loading behavior and context cost.
- Installing a plugin means running someone else's hooks, scripts, and MCP servers with your permissions. Read what it contains, prefer sources you trust, and review updates.
- Namespacing keeps plugin commands from colliding with your own, but a pile of plugins still fills the skill list and the context with descriptions.
- Build a plugin only after the workflow has proven itself in one project — packaging something unstable multiplies its maintenance cost.
