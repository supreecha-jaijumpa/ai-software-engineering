# 2.14 Choosing the Right Mechanism

- Several mechanisms can hold Markdown instructions, but they are not interchangeable. Choose by four questions: when does it load, who triggers it, is it enforced or advisory, and what does it cost to maintain?
- Needed in almost every session and short → `CLAUDE.md`. A convention for one part of the codebase → a path-scoped rule.
- A procedure or body of knowledge needed sometimes → a skill, so only its description is always in context. A workflow with side effects that you want to trigger yourself → a user-invoked skill or command.
- Work that would flood the main context, or that needs a restricted, specialized role → a subagent.
- Something that must happen every time, without exception → a hook. Something that must never happen, or needs human approval → a permission rule.
- Access to a system outside the repository and shell → an MCP server — after checking that an existing CLI is not enough. Sharing a proven setup across repositories → a plugin.
- Common misplacements: procedures in `CLAUDE.md` (always loaded, rarely needed), hard rules written as instructions (not enforced), a subagent for a two-step lookup (expensive), an MCP server for something a CLI already does (noise).
- The default answer is "none of them yet". Add a mechanism when you have seen the same problem twice, and remove it when it stops earning its place.
