# 2.1 Claude Code Operating Model & Sessions

- Claude Code is an agent harness around a model: it runs an agent loop in your terminal or IDE in which the model reads files, runs commands, edits code, and observes the results until the task is done or it needs you.
- A session is one conversation with its own context window, started in a working directory. That directory determines which project instructions and settings are loaded.
- At startup the context already holds content you did not type: the system prompt, tool definitions, loaded instruction files, and short descriptions of available skills, agents, and MCP tools. `/context` shows what is using the window.
- The working unit is the loop from Level 1 — gather context, act, verify — and you can interrupt, redirect, or rewind it at any time.
- Besides the interactive mode there is a non-interactive mode (`claude -p "..."`) for scripts and CI, where nobody is present to approve prompts — permissions must be set deliberately.
- Sessions are independent. A new session knows nothing about the previous one except what is in files (instructions, notes, the repository itself) or what you resume.
- Different surfaces (terminal, IDE extensions, desktop, web) share the same core model of sessions, tools, and configuration, with different interfaces around it.
- Practical consequence: think of each session as a fresh colleague who has read the instruction files and nothing else — and decide what you want that colleague to already know.
