# 2.4 Skills & Progressive Disclosure

- A skill is a folder containing a `SKILL.md` — reusable knowledge or a procedure — stored in `.claude/skills/<name>/` for a project or `~/.claude/skills/<name>/` for yourself.
- Progressive disclosure is the key property: at session start only each skill's name and description are in context. The body of `SKILL.md` loads when the skill is used, and supporting files (references, templates, scripts) load only when the skill reaches for them.
- A skill is triggered in two ways: Claude decides it is relevant based on the description, or you invoke it directly as `/skill-name`.
- The description is therefore the most important line: it must say what the skill does **and when to use it**, in the words a request would actually contain. A vague description means the skill never loads.
- Frontmatter can control behavior — for example restricting which tools the skill may use, or preventing the model from invoking it on its own so that only you can trigger it. Check the docs for the current fields.
- Skills can bundle scripts: deterministic work (validation, scaffolding, data extraction) runs as code, and only its output enters the context.
- Good candidates: procedures you repeat (analyze a requirement, plan an implementation, verify a feature), and knowledge needed sometimes but not always.
- Cost and risk: each skill adds a description to every session, overlapping descriptions cause wrong or missing triggers, and an unmaintained procedure produces confident, outdated work.
