# 2.8 MCP Servers & External Tool Integration

- The Model Context Protocol (MCP) is an open standard for connecting AI applications to external tools and data. An MCP server exposes tools (and optionally resources and prompts); Claude Code acts as the client.
- It is how Claude Code reaches systems outside the repository and shell: issue trackers, databases, browsers, design tools, internal APIs, documentation services.
- Servers run locally as a process or remotely over HTTP, and are added at a scope — just you in this project, the whole project through a shared `.mcp.json`, or you across all projects. `/mcp` shows status and handles authentication.
- Each connected server adds tool definitions to the context, so unused servers cost tokens and make tool selection noisier. Connect what a real workflow needs, not everything available.
- Ask first whether a CLI already solves it: if `gh`, `psql`, or a project script does the job through the shell, an MCP server may add little.
- Security matters more here than anywhere else in this module: a server runs code or holds credentials on your behalf, and whatever it returns enters the context as untrusted content — a classic route for prompt injection.
- Apply least privilege: read-only credentials where possible, scoped tokens, and explicit permission rules for MCP tools that write or send.
- A project-scoped server is part of the team's setup — it needs an owner, documented purpose, and a plan for when the server or its API changes.
