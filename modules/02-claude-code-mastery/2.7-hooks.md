# 2.7 Hooks — Event-Driven Deterministic Automation

- A hook is a command that Claude Code itself runs when a lifecycle event occurs. The harness executes it — the model does not choose to — which makes hooks deterministic where instructions are only probable.
- Events include points such as before a tool runs, after a tool runs, when you submit a prompt, when the session starts, before compaction, and when Claude finishes responding. The exact list and payloads are version-sensitive — check the hooks reference.
- Hooks are configured in settings files, usually with a matcher that selects which tool calls they apply to (for example only file edits, or only shell commands).
- The hook receives details of the event as JSON input and can influence what happens next: a pre-tool hook can block the action and return a reason to Claude; a post-tool hook can feed results back.
- Typical uses: format a file after every edit, run a fast lint or type check, block edits to protected paths, block dangerous command patterns, log activity, send a notification when input is needed.
- Use a hook for "this must happen every time"; use an instruction for "this is how we prefer to work". If a rule in `CLAUDE.md` keeps being forgotten, it probably wants to be a hook.
- Hooks run with your user's permissions and without asking. Review them like any script, keep them fast, make them safe to run repeatedly, and be careful with hooks that arrive from a repository you did not write.
- A slow or flaky hook taxes every action in every session — measure the cost before adding one.
