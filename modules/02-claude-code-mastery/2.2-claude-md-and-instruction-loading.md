# 2.2 CLAUDE.md & Instruction Loading

- `CLAUDE.md` is the entry-point instruction file: its content is loaded into context at the start of every session, so every line is paid for on every turn.
- Locations form a hierarchy — organization-managed policy, user-level (`~/.claude/CLAUDE.md`), project-level (`./CLAUDE.md` or `./.claude/CLAUDE.md`), and personal project notes kept out of version control. Files in parent directories load at startup; files in subdirectories load when Claude works in those directories.
- A `CLAUDE.md` can import other files with `@path/to/file`. Imports are convenient but still load up front — they organize content, they do not save context.
- Its content is delivered as context alongside your conversation, not as an enforced configuration. Claude tries to follow it; nothing guarantees it. Long, vague, or contradictory files are followed less reliably.
- Good content: build/test/lint commands, the few conventions that are not obvious from the code, repository layout hints, and pointers to where detailed knowledge lives.
- Poor content: things the model can read from the code, long tutorials, rarely needed procedures (make those skills), and rules that must never be broken (make those permissions or hooks).
- Test each line with "would removing this cause a mistake?" — if not, remove it. `/init` can generate a starting file and `/memory` shows which instruction files are loaded.
- The project file belongs in version control and deserves review like code: a wrong instruction there misleads every session of every teammate.
