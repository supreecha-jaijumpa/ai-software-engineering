# 7.1 Token Economics — Input, Output & Cached Tokens

- Every model call is billed and limited in tokens of three kinds: input (everything sent), output (everything generated), and cached input (an unchanged prefix reused at a reduced price).
- Input dominates agentic work. Because the model is stateless, the whole conversation — instructions, history, tool results — is sent again on every turn, so cost grows with the length of the session, not just with what you type.
- Output tokens are priced higher and generated more slowly. Long explanations, restated code, and verbose reports cost more than they appear to.
- Caching rewards stability: a consistent start of the context (system prompt, tool definitions, instruction files) is read cheaply; changing that prefix mid-session, or pausing until the cache expires, means paying full price again.
- Fixed overhead exists before you type anything: tool definitions, instruction files, and the descriptions of skills, agents, and MCP tools. More installed capabilities means a higher floor for every turn.
- Tool results are the least visible cost: one unfiltered test log or large file read can outweigh the rest of the session.
- Use the tool's own reporting to see where tokens go — context breakdown and usage or cost summaries — rather than guessing. Exact prices and limits change; look them up when they matter.
- Token cost is only one side of the ledger. The other is your time and the cost of wrong output — which is why the target is cost per verified result, not the lowest token count.
