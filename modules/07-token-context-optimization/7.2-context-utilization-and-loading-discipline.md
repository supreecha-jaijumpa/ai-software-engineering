# 7.2 Context-Window Utilization & Loading Discipline

- Utilization is how full the context window is and with what. The useful question is not "how much room is left?" but "how much of what is loaded is relevant to this task?".
- Load only the context relevant to the current task. Each irrelevant block costs tokens on every turn and competes for the model's attention with what matters.
- Keep the root instruction file concise: it is the one piece of context paid for in every session of every task. Detailed knowledge belongs in references and skills that load selectively.
- Progressive disclosure is the main structural tool — an index always loaded, details on demand — and context compaction is the main runtime tool when a session grows long.
- Compact or restart deliberately at task boundaries rather than letting automatic compaction happen in the middle of delicate work.
- Preserve concise state summaries for long-running work, so that a fresh, small context can replace a large, degraded one without losing the thread.
- Do not over-correct. Reducing context too aggressively starves the model of conventions and constraints, and the resulting mistakes and rework cost more than the tokens saved.
- A simple routine: check context usage at the start (what is my fixed overhead?), at the midpoint (what is growing?), and before a long step (should I compact or hand off first?).
