# 7.5 Cost per Successfully Verified Task

- The metric that matters is the total cost of getting one task to a verified, accepted state — tokens, elapsed time, and human effort — not the token count of a single run.
- Cost per successful task = total cost of all attempts, including failed and reworked ones, divided by the number of tasks that actually passed verification.
- This reframes optimization. A lean workflow that fails a third of the time can cost more per success than a heavier one that passes first time; an extra review step that prevents rework can lower total cost while raising tokens per run.
- Measure cost alongside correctness and rework, on the same evaluation set and with the same criteria, whenever you compare workflow versions.
- The usual sources of waste, in rough order: rework from unclear requirements, unfiltered output and broad reading, bloated always-loaded context, duplicated exploration across agents, and loops without bounds.
- Human time is normally the largest cost. A change that saves tokens but adds review burden or interruptions is rarely a saving.
- Avoid false economy: cutting context, skipping verification, or dropping the independent check reduces tokens per run and raises the chance of an expensive failure later.
- Report cost the way you report quality — per task type, as a trend, next to success and rework rates — so that a cost decision is always made with its effect on correctness in view.
