# 1.9 Hallucinations, Uncertainty & Verification

- A hallucination is a fluent, confident output that is not grounded in fact: an API that does not exist, a file path that was never read, a test that "passes" without having been run.
- It is not a rare bug but a consequence of how generation works — the model produces the most plausible continuation, and plausible is not the same as true.
- Risk is highest when the answer is not in context: unfamiliar libraries, version-specific behavior, internal conventions, and anything the model was asked to recall rather than look up.
- The model's stated confidence is weak evidence. It can be asked to list assumptions and open questions — that is useful — but its self-assessment is still not verification.
- Verification means establishing correctness independently of the model: run the tests, run the type checker and the build, read the diff, call the endpoint, check the documentation.
- Prefer checks that can fail. "The agent says it works" cannot fail; a test run with an exit code can.
- Completion claims deserve particular suspicion: "all tests pass" should come with the command and its output, not as a sentence.
- Practical consequence: for every task decide beforehand what evidence would convince you, and ask for that evidence instead of an assurance.
