# 1.2 Tokens & Tokenization

- Models do not read characters or words; text is split into tokens — common words are often one token, rare words, identifiers, and symbols are split into several pieces.
- Rule of thumb for English prose: one token is roughly three to four characters. Code, JSON, minified files, and non-Latin scripts such as Thai usually cost more tokens for the same visible length.
- Everything is counted in tokens: context-window limits, pricing, rate limits, and often latency. "How big is this?" always means "how many tokens?".
- Tokenization differs between model families, so a token count is only exact for a specific model — use the tool's own usage reporting rather than estimating by hand.
- Tokenization explains some odd weaknesses: counting letters, reversing strings, or exact character positions are hard because the model never sees individual characters.
- Verbose formats are expensive: a large JSON log, a lockfile, or an HTML dump can cost more tokens than the whole source file you actually care about.
- Practical consequence: before pasting or loading something, ask what it costs and whether a filtered version (a grep, a summary, the failing lines only) would carry the same information.
