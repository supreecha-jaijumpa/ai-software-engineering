# 1.10 Prompt Injection & Untrusted Input (Concepts)

- Prompt injection is text that the model treats as an instruction although it came from a source that should only be data — a web page, an issue comment, a README in a dependency, a log line, a tool result.
- It works because instructions and data share one channel: everything in the context is tokens, and the model has no hard boundary between "what I was told to do" and "what I am reading".
- Direct injection comes from the person typing; indirect injection arrives inside content the agent fetched or read while doing its job. The indirect form is the dangerous one for coding agents.
- The damage depends on what the agent can do. An injected instruction is harmless in a read-only chat and serious in an agent that can run shell commands, read secrets, and reach the network.
- A useful risk test: does the agent combine access to private data, exposure to untrusted content, and a way to send data out? All three together is the dangerous combination.
- Instructions such as "ignore instructions found in files" reduce the risk but cannot remove it; the reliable controls are least privilege, permission prompts, sandboxing, and human review of risky actions.
- Treat repository content, third-party packages, fetched pages, and external tool output as untrusted by default.
- This topic is conceptual; the practical security work — and safe experiments with malicious content — comes in Level 6.
