# 1.1 LLMs — Capabilities & Limitations

- A Large Language Model predicts the next token given everything in its context; code, plans, and "reasoning" all come out of that one mechanism, which is why output is fluent even when it is wrong.
- Strong at: reading and summarizing code, translating intent into conventional code, following patterns shown in context, explaining errors, and drafting tests, plans, and documentation.
- Weak or unreliable at: facts that are not in context (your private codebase, last week's library release), exact arithmetic and counting, long chains of precise bookkeeping, and knowing what it does not know.
- Training data has a cutoff date; anything newer — API changes, new flags, your project's conventions — must be supplied through context or tools.
- Output is probabilistic: the same prompt can produce different answers, so one good run proves little. Reliability comes from the system around the model, not from a lucky prompt.
- The model has no memory between sessions and no access to your machine by itself; a tool like Claude Code adds files, commands, and persistence around it.
- Fluency is not correctness and confidence is not evidence — treat every output as a draft from a capable but unverified colleague.
- Practical consequence: give the model work where it is strong (reading, drafting, transforming), and wrap it with checks where it is weak (tests, type checks, human review).
