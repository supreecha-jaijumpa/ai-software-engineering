# 1.3 Input, Output, Cached Input & the Context Window

- The context window is everything the model can see for one response: system instructions, tool definitions, loaded project instructions, the conversation so far, tool results, and the answer it is writing. It has a hard token limit.
- Input tokens are what is sent to the model; output tokens are what it generates. Output is normally priced higher and is generated more slowly than input is read.
- The model is stateless: in a conversation, the whole history is sent again on every turn. A long session therefore gets more expensive per turn, not just in total.
- Prompt caching lets a provider reuse an unchanged prefix of the input at a fraction of the normal input price. It rewards a stable beginning (instructions, tool definitions) and is invalidated when that prefix changes or the cache expires.
- Tool results count as input too — a single command that prints thousands of lines can consume more of the window than hours of conversation.
- A full window does not fail gracefully: older content is summarized or dropped (compaction), and details the model was relying on can disappear.
- Quality also degrades before the limit: with a lot of loosely relevant material in context, the model is more likely to miss or mix up instructions.
- Practical consequence: watch the context meter the way you watch memory in a long-running process, and know which content in the window is permanent, which is growing, and which is wasted.
