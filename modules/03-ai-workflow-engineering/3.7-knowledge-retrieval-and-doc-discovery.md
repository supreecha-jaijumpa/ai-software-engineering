# 3.7 Knowledge Retrieval & Documentation Discovery

- Retrieval is how knowledge that is not in context gets found when needed: searching the codebase, reading documentation, querying an external system, or asking a human.
- In a coding agent the main retrieval tool is ordinary search — file names, content search, following imports — and it works well when the repository is organized and named predictably.
- Discovery is the first half of the problem: the model cannot retrieve what it does not know exists. An index — a short list of documents with one line on when each is relevant — makes knowledge findable.
- Good documentation for retrieval is the same as good documentation for people: descriptive file names, one topic per file, a summary at the top, and terms that match how questions are asked.
- Code is the most current documentation. Prefer pointing at a canonical example ("new endpoints follow the pattern in orders/handler") over prose that can drift from the code.
- For external and version-sensitive knowledge — library APIs, tool behavior — retrieve from official documentation rather than relying on the model's memory.
- Retrieved content is input, with two costs: tokens, and trust. Fetched pages and third-party files are untrusted and may be wrong, outdated, or adversarial.
- Measure discovery: give a fresh session a question the documentation should answer and watch whether it finds the right file. If not, fix the index or the naming, not the prompt.
