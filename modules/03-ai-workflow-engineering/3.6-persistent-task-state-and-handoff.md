# 3.6 Persistent Task State & Handoff Notes

- Persistent task state is a small file that records where a piece of work stands, so that it can be resumed after an interruption, a compaction, a new session, or by a different person or agent.
- A handoff note is the same idea at a boundary: what the next context needs in order to continue without re-reading the whole history.
- Useful contents: the goal and acceptance criteria, the approved plan, what is done (with evidence), what is in progress, decisions and their reasons, known problems, and the exact next step.
- State records facts, not narrative. "Tests for the draft flow pass (command, date)" is state; "we had a long discussion about validation" is not.
- Update it at checkpoints — after a plan is approved, after a verified step, before stopping — not continuously, and keep it short enough to be read at the start of every session.
- The state file is the source of truth for the workflow; the conversation is disposable. If they disagree, either the file is wrong and gets fixed, or the conversation is discarded.
- Stale state is dangerous: a note claiming "implemented and verified" for something later reverted will be believed. Record how each claim can be re-checked.
- The test of a handoff: start a fresh session, give it only the note, and see whether it can continue correctly without asking what happened before.
