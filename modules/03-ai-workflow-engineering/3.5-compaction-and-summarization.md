# 3.5 Context Compaction & Summarization

- Compaction replaces a long history with a shorter summary so work can continue inside the window. Summarization is the general technique; compaction is its automatic or on-demand use on the conversation itself.
- Every summary is a decision about what to forget. Details that seemed unimportant to the summarizer — an exact error string, a constraint mentioned once — may be exactly what is needed later.
- Automatic compaction happens when the window is nearly full, at a moment you did not choose. Compacting deliberately at a natural breakpoint, with a stated focus, keeps what matters.
- What survives reliably is what lives outside the conversation: instruction files are reloaded, and files on disk can be read again. What lives only in chat does not.
- A structured summary beats a narrative one: goal, decisions and their reasons, current state, files touched, open problems, next step, how to verify.
- Summarize tool output at the source as well — "12 tests failed; first failure: …" instead of the full log — so the raw material never enters the window.
- Repeated compaction compounds loss, like re-saving a compressed image. For long work, a written state file plus a fresh session is more reliable than a session compacted many times.
- Decide before a long task what must survive compaction, and put exactly that in a file rather than trusting the summary.
