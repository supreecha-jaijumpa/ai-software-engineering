# 3.9 Reusable Workflow Composition

- Composition means building larger workflows out of small, single-purpose pieces — a requirement analysis, a planning step, an implementation step, a verification step — instead of one giant instruction.
- Pieces compose through artifacts, not through shared chat memory: one step writes a requirements file, the next reads it. The artifact is the interface.
- Explicit interfaces make steps replaceable, testable in isolation, and resumable — a workflow can restart from the last good artifact instead of from the beginning.
- Keep each skill focused on one outcome. A "do everything" skill is hard to trigger correctly, impossible to test, and loads instructions for five phases when one is running.
- A workflow document can describe the order and the gates (for example: analysis → plan → human approval → implementation → verification) while each step stays an independent skill.
- Reuse comes from parameterizing by artifact and scope, not from abstraction for its own sake: the same verification skill serves a frontend change and an API change if it reads the acceptance criteria from a known place.
- Avoid hidden coupling: a step that only works because of something said earlier in the conversation will fail when run alone or after compaction.
- Compose only what repeats. Two real uses justify extracting a shared step; one use does not.
