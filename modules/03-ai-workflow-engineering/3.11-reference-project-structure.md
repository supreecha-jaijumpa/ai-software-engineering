# 3.11 A Reference Project Structure (.ai/ + .claude/)

- This is a proposed convention for organizing AI workflow files, not a Claude Code standard. `.claude/` is what the tool itself reads; `.ai/` is a project choice for knowledge and working state.
- Suggested responsibilities — `CLAUDE.md`: concise entry point with essential instructions and pointers. `.claude/rules/`: enforceable project conventions and constraints. `.claude/skills/`: reusable procedures. `.claude/agents/`: specialized agent definitions. `.claude/settings.json`: permissions and hooks.
- `.ai/project/` holds stable project knowledge such as `architecture.md`, `conventions.md`, and `tech-stack.md` — read on demand, pointed to from `CLAUDE.md`.
- `.ai/features/<feature>/` holds one feature's package: `requirements.md`, `feature-map.md`, `decisions.md` — loaded when that feature is being worked on.
- `.ai/workflows/` describes how work proceeds (`development.md`, `testing.md`, `release.md`), and `.ai/state/current-task.md` holds the persistent state of the work in progress.
- The structure maps directly onto the context layers of topic 3.2: project, feature, and task each get a home with a different lifetime.
- Do not create every file by default. An empty or boilerplate file is negative value: it costs attention and suggests knowledge that is not there. Add a file when there is real content and a loader for it.
- For each file, be able to state why it exists and who or what loads it. If existing documentation already covers a topic, point to it rather than copying it into `.ai/`.
