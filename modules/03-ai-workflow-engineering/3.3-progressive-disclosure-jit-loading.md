# 3.3 Progressive Disclosure & Just-in-Time Context Loading

- Progressive disclosure means showing a small index first and loading details only when they are needed. Just-in-time loading is the same idea in time: context enters the window at the moment it becomes relevant.
- The basic shape is three tiers: an always-loaded pointer ("API conventions: see docs/api.md"), a document loaded when the topic comes up, and deep references loaded only for specific sub-problems.
- Claude Code provides the building blocks: skill descriptions with on-demand bodies, path-scoped rules, nested instruction files for subdirectories, subagents that read without filling the main context, and plain pointers the model can follow by reading a file.
- A pointer only works if it says when to follow it. "See architecture.md" is weak; "before changing module boundaries or adding a service, read architecture.md" is a trigger.
- The alternative — loading everything up front — is simpler and sometimes right: for a small project, a single short file beats an elaborate hierarchy.
- The trade-off: progressive disclosure saves context and focus, but adds the risk that the model does not load something it needed. Critical constraints stay in the always-loaded tier or in enforced controls.
- Test it empirically: run the same task with everything loaded and with progressive disclosure, and compare correctness, rework, and tokens. Keep the structure only if it wins.
- Signs of over-engineering: more pointer files than content, chains of references three levels deep, and documents nobody — human or model — ever opens.
