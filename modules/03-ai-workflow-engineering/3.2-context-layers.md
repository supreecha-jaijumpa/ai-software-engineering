# 3.2 Context Layers — Global, Project, Feature, Task, Runtime

- Global context is what holds for you everywhere: personal preferences and habits, in user-level instructions. Keep it small — it is added to every session of every project.
- Project context is what holds for the whole repository: architecture overview, conventions, tech stack, commands. It lives in `CLAUDE.md`, rules, and project reference documents.
- Feature context is what holds for one feature while it is being built or changed: requirements, the feature map, decisions made. It should be loadable as a package and ignorable by everyone else.
- Task context is what holds for the current unit of work: the goal, the acceptance criteria, the plan, the current state. It changes daily and is written in a short state or handoff file.
- Runtime context is produced while working: files read, command output, errors, search results. It is the largest and noisiest layer, and it disappears with the session unless something is written down.
- Layers differ in stability and lifetime — from years (global) to minutes (runtime) — and stable layers should never contain volatile facts.
- Knowledge flows upward only on purpose: a discovery made during a task becomes a feature decision, or a project convention, when someone decides it should — not by pasting chat output into `CLAUDE.md`.
- A useful diagnostic for any instruction: which layer does it belong to? A task detail in project context is noise for everyone; a project convention living only in task notes will be forgotten.
