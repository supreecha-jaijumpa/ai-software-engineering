# 5.12 Cost & Latency Trade-offs of Multi-Agent Systems

- Multi-agent workflows typically use several times the tokens of a single agent on the same task: each agent has its own start-up context, explores for itself, and writes a report that another agent then reads.
- What is bought with that cost: shorter elapsed time through parallelism, cleaner contexts through isolation, and independent verification. If none of the three is needed, a single agent is the better design.
- Elapsed time improves only as far as the dependency graph allows, and coordination — briefing, waiting, integrating, re-verifying — is added on top.
- Duplicate exploration is the most common waste: three agents each reading the same files to understand the same feature. A shared map or brief prepared once prevents it.
- Quality can go either way. Isolation and independent review raise it; lost context at handoffs and integration mistakes lower it. Only measurement tells you which effect won.
- Compare against a single-agent baseline on the same task: quality of the result, elapsed time, token use, rework, and how often a human had to step in.
- The right unit is cost per successfully verified task. A cheap run that needs to be redone is expensive; an expensive run that is correct the first time may be cheap.
- A defensible default: single agent first; a subagent for isolated research or independent review; parallel implementation only with a stable contract, isolated working directories, and a reason the time matters.
