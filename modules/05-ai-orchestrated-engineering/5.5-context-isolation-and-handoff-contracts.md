# 5.5 Context Isolation & Handoff Contracts

- Each agent in a multi-agent workflow has its own context. Isolation keeps one agent's noise, false starts, and assumptions out of another's — and it means nothing is shared unless it is passed deliberately.
- A handoff contract defines what crosses the boundary in each direction: the inputs a worker receives and the output it must return, in a stated format.
- Input side: goal, scope, constraints, pointers to artifacts (the requirement file, the feature map, the API contract) and the definition of done. Point to files rather than retyping their contents.
- Output side: a fixed structure the receiver can rely on — for example findings with file and line references, a confidence note, what was not checked, and open questions.
- Structured output makes results comparable and mergeable; three reviewers answering in three different free-form styles cannot be combined mechanically.
- A contract should require the worker to separate what it verified from what it inferred. Without that, every statement arrives with the same apparent certainty.
- Handoffs through files are sturdier than handoffs through messages: a file persists, can be read by several agents and by you, and survives compaction of the orchestrator's context.
- Treat a worker's report as input to be checked, not as an instruction to be followed — it can be wrong, and it may contain text carried over from untrusted content it read.
