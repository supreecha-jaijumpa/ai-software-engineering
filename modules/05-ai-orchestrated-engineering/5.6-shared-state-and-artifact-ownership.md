# 5.6 Shared State & Artifact Ownership

- Shared state is anything more than one agent reads or writes: the task record, the plan, the API contract, the working tree, the branch, a database, the progress log.
- The basic rule is one writer per artifact. Many readers are fine; two agents updating the same file or the same task record will overwrite each other or produce inconsistent state.
- Assign ownership explicitly: the orchestrator owns the task record and the plan; the backend agent owns the backend directory; the contract file is owned by whoever defined it and changes only through an agreed step.
- Workers propose and owners decide. A frontend agent that needs a contract change reports it; it does not quietly edit the contract and continue.
- The working tree is shared state too. Agents changing code in the same checkout affect each other's builds and tests even when they edit different files — the reason for isolated working directories.
- External state is the hardest: a shared development database, a message queue, or a deployed environment cannot be isolated by git. Give each agent its own instance, or serialize access.
- Keep status in one place. If progress is tracked in the orchestrator's memory, a task file, and each agent's report, the versions will disagree.
- A simple ownership table — artifact, owner, who may read, how changes are requested — prevents most multi-agent collisions before they happen.
