# 5.8 Git Worktrees & Isolated Working Directories

- A git worktree is an additional working directory attached to the same repository, checked out on its own branch. Several worktrees share one history but have separate files on disk.
- Basic commands: `git worktree add <path> -b <branch>` creates one, `git worktree list` shows them, `git worktree remove <path>` deletes one. A branch can be checked out in only one worktree at a time.
- For agents, a worktree gives each parallel task its own files: edits, builds, and test runs in one do not disturb another, and each task ends as a normal branch that can be reviewed and merged.
- It is lighter than cloning the repository several times — no duplicated history — and more honest than several agents sharing one directory.
- A fresh worktree has the tracked files only. Dependencies, build output, local environment files, and generated code are missing until installed or created — a common reason for "works here, fails there".
- Worktrees isolate files, not everything else: ports, local databases, caches, and external services are still shared and can still collide.
- Claude Code offers built-in support for running sessions and subagents in worktrees; check the current documentation for the exact options rather than assuming them.
- Housekeeping matters: name worktrees after their task, merge or discard the branch when done, and remove the worktree — forgotten worktrees and stale branches accumulate quickly.
